⏱️ 1. The 60-Second Elevator Pitch

"Tell me about this project on your resume:"

"In this project, I built an end-to-end Generative AI Text-to-SQL analytics system that allows non-technical business stakeholders—such as product managers, sales executives, and operations leads—to query complex relational databases using natural language instead of writing SQL.

I integrated Google Gemini with LangChain and LangGraph to dynamically inspect database schemas, translate plain-English questions into dialect-accurate SQL, execute queries safely against MySQL and SQLite, and synthesize tabular data into concise conversational insights.

To address latency and reasoning needs, I engineered a dual-mode engine: a fast direct LCEL chain for high-frequency queries, and an autonomous ReAct agent with syntax checking and self-correction for exploratory multi-table analysis. Finally, I benchmarked accuracy using the RAGAS evaluation framework and deployed a full interactive Streamlit interface."

🏗️ 2. Architectural Walkthrough

Explain this 4-step pipeline to technical interviewers:

  1. Dynamic Schema Extraction: Extracts table names, DDL, and sample rows dynamically using SQLAlchemy's SQLDatabase.get_table_info().
  2. Prompt Construction & Guardrails: Injects schema and user questions into structured prompt templates, instructing Gemini to generate single-pass SQL with strict stop tokens (\nSQLResult:).
  3. Dual Execution Engine:
    • LCEL Direct Chain: Fast 1-pass execution for simple queries.
    • LangGraph ReAct Agent: Utilizes SQLDatabaseToolkit (4 tools: ListSQLDatabaseTool, InfoSQLDatabaseTool, QuerySQLCheckerTool, QuerySQLDatabaseTool) for iterative reasoning and automated error recovery.
  4. Synthesis & Presentation: An LLM synthesizer turns raw database rows into conversational summaries, presented in a Streamlit chat UI alongside SQL queries and interactive dataframes.

⚖️ 3. Direct Chain vs. ReAct Agent

Feature LCEL Direct Chain LangGraph ReAct Agent
Latency 1 – 2 seconds (Fast) 4 – 8 seconds (Multi-step)
Inference Calls 2 fixed calls 3 to 7 iterative tool calls
Self-Correction Fails if query has syntax error Reads database error & self-corrects
Best For Known queries, simple aggregations Exploratory analytics, ambiguous joins

🛡️ 4. Security & Guardrails (Crucial for Interviews)

Q: How do you prevent SQL Injection and destructive commands (DROP, DELETE, UPDATE)?

Answer: We enforce security at 4 independent layers:

  • Read-Only Database Role: The database connection uses credentials strictly granted SELECT privileges. Destructive statements are blocked directly by the database engine.
  • Prompt-Level Constraints: The system prompt enforces outputting read-only queries only.
  • AST Parsing: Validates with sqlparse that the root statement is strictly a SELECT.
  • Execution Limits: Enforces top_k=5 to prevent denial-of-service memory exhaustion.

Q: How do you handle schema scaling for databases with 100+ tables?

Answer: We implement Schema RAG. We store table descriptions and column metadata as vector embeddings in ChromaDB/FAISS. When a user asks a question, we semantically retrieve only the top 3-5 relevant table schemas and pass them to the LLM, avoiding prompt bloat and the "needle-in-a-haystack" degradation.

Q: How did you evaluate the system with RAGAS?

Answer: We constructed an EvaluationDataset of SingleTurnSample items containing user inputs, retrieved schemas, generated SQL, and ground-truth references. We measured Context Precision (schema retrieval quality), RubricsScore (1-5 helpfulness rubric evaluated by an evaluator LLM), and AspectCritic (maliciousness/prompt injection detection).

Q: Why Google Gemini 2.0 Flash?

Answer: Extremely fast Time-to-First-Token (TTFT), high instruction-following accuracy for structured SQL generation, low token cost for enterprise usage, and a massive context window for large schema contexts.
